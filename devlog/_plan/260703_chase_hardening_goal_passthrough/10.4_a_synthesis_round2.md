## Finding

### ARCH-A3 — Cluster B implementation bullets still clamped unbounded B/GB branches

Decision: accept.

The first A synthesis changed acceptance criteria to preserve large values above the supported B/GB range, but the implementation bullets still told executors to apply `compactIntegerUnit()` to the unbounded B branch and `formatByteUnit()` to the unbounded GB branch. That contradicted the acceptance criteria and could cap large values forever.

Plan changes:

- Cluster B now states `compactIntegerUnit()` applies only to bounded integer transitions: K-before-M and M-before-B.
- The unbounded `>=10_000_000_000` B branch stays on current `Math.round(n / 1_000_000_000)` behavior unless a later phase adds T suffixes.
- The byte helper now applies only to bounded KB-before-MB and MB-before-GB transitions.
- The unbounded GB branch stays on current `(bytes / (1024 * 1024 * 1024)).toFixed(1)` behavior unless a later phase adds TB suffixes.
- Format tests now include large-value preservation checks: `formatNumber(1_000_000_000_000) === "1000B"` and `formatBytes(1024 ** 4) === "1024.0GB"`.

## Result

The plan now aligns Cluster B implementation instructions with acceptance criteria and explicitly avoids adding T/TB display policy in this phase.
