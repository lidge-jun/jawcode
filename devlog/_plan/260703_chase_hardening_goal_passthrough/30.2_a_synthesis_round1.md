## Findings and decisions

### PLANNER-A1 — async teardown contract too narrow

- Auditor claim: Cluster A only promised to flush pending delivery queues, but the chase target says pending async background jobs must survive or delay termination safely; still-running retained jobs were unproven.
- Root cause: the draft overloaded “async job delivery/lifecycle drain” and did not separate terminal delivery from still-running job survival.
- Decision: accept.
- Plan change: Cluster A now defines the exact contract: top-level teardown makes a bounded attempt to deliver already-terminal queued results owned by the session; still-running jobs are not waited to completion in Phase 30 and must remain retained/addressable by `AsyncJobManager`, not cancelled or marked delivered. Tests must cover pending terminal delivery, timeout, owner isolation, and still-running retention/addressability.

### PLANNER-A2 — conditional discovery-ordering deferral had no boundary

- Auditor claim: Cluster E deferred task/agent discovery ordering “unless a direct session-integrity bug is found,” but the optional path had no target files, acceptance criteria, or tests.
- Root cause: an escape hatch remained from source-card triage without a P-stage contract.
- Decision: accept.
- Plan change: task/agent discovery ordering and disabled plugin ordering are now unconditionally deferred for Phase 30.

### ARCH-A1 — compact-failure behavior contradicted existing contract

- Auditor claim: the plan required approve-and-compact failure to skip synthetic plan execution, but `InteractiveMode` dispatches best-effort unless compaction is explicitly cancelled.
- Local evidence: `packages/coding-agent/src/modes/interactive-mode.ts:1667-1668` says cancellation skips dispatch and failure proceeds best-effort; `:1696-1732` returns only on `compactOutcome === "cancelled"` and otherwise sends the synthetic plan-approved prompt.
- Decision: accept.
- Plan change: Cluster C now preserves failed-compaction dispatch-after-approval and only suppresses execution for refine/cancel/no-selection/cancelled-compaction/deferred-switch paths.

### ARCH-A2 — wrong private method name for persistence owner

- Auditor claim: `#persist` does not exist; the actual hot path is `_persist(entry: SessionEntry)` and related `#rewriteFile` / `#ensurePersistWriter`.
- Decision: accept.
- Plan change: Cluster B now names `#rewriteFile`, `#ensurePersistWriter`, `_persist(entry: SessionEntry)`, flush/close ordering, and `NdjsonFileWriter.isOpen()`.

## Residual risk

The plan still permits noop receipts when current behavior is already correct. B-stage must record exact inspected source paths and focused tests for any noop cluster; otherwise the split-card closure becomes hand-wavy nonsense with better typography.
