# 20.065 — OMP chase: browser, bash, commit, and process-boundary resilience

> MOC: [20_omp_chase_MOC](./20_omp_chase_MOC.md) · G2 · ⬜ · P3 — Bound browser and shell teardown, preserve commit completion ordering, and isolate terminal/process failures.

## Chase Scope

This card tracks lifecycle failures where useful work exists but cleanup, cancellation, or a transport boundary loses it. The OMP delta covers browser acquisition and selector watchdogs, isolated-shell cancellation, agentic commit ordering, stderr/postmortem cleanup, internal URL recovery, launch PTY rendering, and in-process coreutils behavior.

JWC owns comparable browser, shell, commit, session, Markdown, and postmortem surfaces, but its implementation layout differs. The card therefore keeps the OMP changes as evidence for focused adaptation; it does not authorize a broad browser/runtime replacement or a vendored-coreutils import.

- [ ] Prove browser close, tab teardown, selector polling, and cmux waits are bounded in JWC.
- [ ] Prove shell cancellation reaches isolated/native child processes without converting timeout provenance.
- [ ] Prove agentic commit completion precedes teardown and process exit.
- [ ] Decide whether internal URL disk fallback and postmortem/stderr ownership have JWC-equivalent gaps.
- [ ] Treat OMP launch/coreutils work as a separate owner decision before any implementation.
