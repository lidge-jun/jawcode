# 20.063 — omp chase: session settings and startup lifecycle

> MOC: [20_omp_chase_MOC](./20_omp_chase_MOC.md) · G2 · ⬜ · P3 — keep startup, continuation, and shutdown automation bounded by explicit user and session state.
> Reviewed source: OMP `7aa1d581c..b0d04e517` (`origin/main`, v16.4.2→v17.0.1) vs JWC worktree.

## Chase Scope

This card covers settings lookup, plan re-entry, optional prewalk automation, extension loading, session continuation/recovery, startup changelog/title output, non-interactive disposal, print-mode feedback, and aborted-turn learning guards. The common boundary is lifecycle ownership: startup helpers must not capture stale request/session state, continuation must be opt-in and one-shot, and headless exits must await resource disposal.

JWC has settings, plan/goal/task runtimes, print and RPC modes, startup changelog utilities, title generation, and an async `AgentSession.dispose()`. It does not have OMP's `prewalk`, `autolearn`, or `exit-diagnostics` owners. Those features are reference-only unless mapped to an existing JWC product contract; importing their names or state machine would duplicate JWC's goal/plan/task lifecycle.

All 37 D13 commits are retained. Platform packaging, title policy, verbosity defaults, and AST-tool defaults are residual slices that should not be bundled with session disposal.
