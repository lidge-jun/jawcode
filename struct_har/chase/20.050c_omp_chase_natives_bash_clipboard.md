## Why This Sub-Card

This slice spans two native/platform seams: Rust shell output crossing the N-API callback boundary under
backpressure and timeout, and Windows clipboard image recovery when the primary library cannot decode or
access the payload. JWC owners are `crates/pi-natives/src/shell.rs`, `crates/pi-shell/src/shell.rs`,
`packages/coding-agent/src/tools/bash.ts`, `crates/pi-natives/src/clipboard.rs`, and
`packages/coding-agent/src/utils/clipboard.ts`, with native and clipboard tests under `packages/natives/test/`
and `packages/coding-agent/test/utils/`.

JWC currently uses unbounded Rust channels for the native shell chunk bridge and has timeout coverage, but
not OMP's named crash regression. Its clipboard layer has an `arboard` owner plus a JWC-specific WSL-first
PowerShell bridge; no `CF_DIB` decoder is present. The anchors remain platform correctness references and
must be evaluated against supported JWC execution paths before any implementation decision.

## Reference Decisions

| commit group | decision | rationale |
| --- | --- | --- |
| Shell backpressure (`5d1e25f83`) | **reference/adapt by invariant** | A slow JS callback must not permit unbounded native output growth or deadlock completion. JWC exposes the same Rust/N-API seam, but its current `mpsc::unbounded_channel` bridge and separate `pi-shell` byte streams require a JWC-specific capacity, loss, and shutdown policy. |
| Timeout crash contract (`4f8c34174`) | **reference/adapt by invariant** | Timeout, producer shutdown, bridge drain, and callback disposal must have a deterministic order. JWC has native timeout tests and `bash.ts` lifecycle handling, but the exact issue-4866 regression file is absent, so equivalence is not established. |
| Windows `CF_DIB` (`606c51a7b`) | **reference** | Direct DIB decoding is relevant only if JWC's supported native Windows clipboard path encounters the same `arboard` failure mode. The current Rust owner has no `CF_DIB` branch; dependency and unsafe/platform surface changes require a separate decision. |
| PowerShell fallback (`cab5c4b62`) | **reference/compare** | JWC already uses PowerShell as a WSL bridge before falling through to native access and tests no-payload/non-zero cases. OMP's native-throw fallback order is not identical, so compare failure semantics rather than copying its dispatch sequence. |
