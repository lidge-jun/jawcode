# 20.078 — OMP chase: bash timeout, PTY shell, IRC, and registry lifecycle

> MOC: [20_omp_chase_MOC](./20_omp_chase_MOC.md) · G2 · ⬜ · P3 — Preserve timeout/abort distinctions and lifecycle ownership without importing OMP's registry architecture wholesale.

## Chase Scope

This card groups the shell and lifecycle fixes that share one boundary: a caller must know whether work completed, timed out, was aborted, or became unavailable while another lifecycle transition was in progress. The OMP changes distinguish timeout results from user aborts, drain pipeline output before returning, preserve compatible PTY shells, retain bash ownership across session transitions, and serialize IRC delivery with registry park/dispose operations.

JWC already has mature bash timeout, persistent-shell, PTY, and IRC surfaces, but its ownership graph differs. In particular, OMP's `irc/bus.ts` and `registry/agent-lifecycle.ts` do not exist here. The useful chase is therefore to lock observable semantics first, then adapt only the pieces that fit JWC's current `BashTool`, session, IRC tool, and agent registry owners.

- [ ] Distinguish timeout, user abort, non-zero exit, and missing-status outcomes in one focused contract matrix.
- [ ] Verify that pipeline tail output drains before timeout completion without reintroducing cold-spawn flakes.
- [ ] Preserve compatible PTY shell selection and persistent bash ownership across session/branch transitions.
- [ ] Verify `uv run --extra` minimization without changing the command's argument grouping.
- [ ] Map IRC park/dispose delivery serialization onto JWC's actual registry before adapting any OMP lifecycle code.
