## Chase Scope

This card covers the OMP repair sequence around PlanYolo entry/exit, failed tool refreshes, mounted xdev tools, runtime tool selection, essential built-in classification, and per-request image generation. The common invariant is transactional convergence: a mode or registry transition either installs the complete new tool state with all safeguards intact, or restores the previous state without leaking a partial transport, presentation, or selection update.

JWC has a different workflow and tool architecture. It has native plan/goal state, generic built-in and MCP discovery, ACP and jaw-interview wrappers, and a multi-provider `generate_image` tool. It has no `PlanYolo`, xdev tool owner, or auto-learn controller. OMP names and state machines therefore remain reference-only; only the rollback, classification, and wrapper-preservation invariants are portable.

All 18 matching commits are retained. Later `generate_image` default/key follow-ups belong with 20.079; custom-loader stdin restoration belongs with 20.077.

- [ ] Reproduce a failed JWC tool refresh and prove the previous registry, active set, prompt, and persisted selection remain coherent.
- [ ] Verify ACP and jaw-interview safeguards survive every tool re-registration and restore path.
- [ ] Test re-registered built-ins with omitted `loadMode` against JWC essential/discoverable classification.
- [ ] Map xdev transport invariants to JWC capability/local-protocol owners only where an equivalent owner exists.
- [ ] Keep OMP PlanYolo and auto-learn state machines out of JWC unless a product contract explicitly adopts them.
- [ ] Compare OMP per-request image provider routing with JWC's existing `generate_image` implementation.
