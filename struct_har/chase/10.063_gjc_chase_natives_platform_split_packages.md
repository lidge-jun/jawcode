## Why This Is A Gap

GJC v0.7.8 split the monolithic natives package into per-platform packages (`natives-darwin-arm64`, `natives-darwin-x64`, `natives-linux-arm64`, etc.), each with its own `package.json` and README, plus `bun.lock`/root `package.json` workspace wiring and an updated split plan doc. JWC currently ships a single `@jawcode-dev/natives` package (`packages/natives/package.json`). This is a packaging/distribution-architecture decision: per-platform packages reduce install footprint (only the matching platform binary is fetched) but add release/workspace complexity.

Behavioral surface:
1. `@jawcode-dev/natives` split into per-platform sub-packages (darwin-arm64, darwin-x64, linux-arm64, …).
2. Root `package.json` + `bun.lock` workspace wiring for the new packages.
3. `docs/natives-package-split-plan.md` updated to reflect the executed split.
