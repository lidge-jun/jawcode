## Chase Scope

This card tracks a single source of truth for context tokens and percentage. Upstream makes provider-reported usage authoritative, uses the last total only as the anchor for post-response trailing estimates, carries nullable totals and provenance, invalidates through an agent-owned context revision, and serves the same cached snapshot to status, `/context`, ACP, notifications, and RPC.

The purpose is not only performance. Divergent heuristics can make context percentage jump between surfaces, misattribute cache misses, and obscure whether a number is provider evidence or an estimate. JWC needs one explicit snapshot contract before any UI-specific optimization is accepted as equivalent.

## Worktree Verification

JWC's `AgentSession.getContextUsage()` reads the latest valid assistant usage after compaction and returns nullable tokens immediately after a compaction boundary. Its `ContextUsage` interface already supports nullable token and percent values, and `Usage.estimated` can distinguish provider-estimated usage metadata.

Parity stops there. `#estimateContextTokensWith()` calculates both provider-anchored trailing usage and a full-message estimate, then returns `Math.max(usageTokens + trailingTokens, estimated)`. Separately, `StatusLine.getCachedContextBreakdown()` tokenizes messages plus non-message inputs and uses that result for the status percentage. No agent-owned context revision, shared snapshot object, or usage provenance field appears in the focused sweep. Status, `/context`, and RPC therefore do not yet have a proven single provider-authoritative snapshot.
