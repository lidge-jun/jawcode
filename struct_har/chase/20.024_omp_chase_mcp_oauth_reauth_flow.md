## Why This Is A Gap

OMP v16.2.5→v16.2.9 hardened the MCP OAuth login/reauth flow: oauth login now races against cancellation, callback port handling fails fast when busy (instead of advertising a random one) while preserving random-port fallback for fresh dynamic-client-registration, Esc cancels `/mcp reauth` and `/mcp add` OAuth flows, the login screen is forced before consent on reauth, prompt behavior is aligned with the MCP SDK, and npx/non-npx cmd-shim launching is preserved (with a gemini oauth helper reuse). JWC's MCP surface can use this as a reference for its own oauth UX and shim launch robustness.

Behavioral surface:
1. MCP oauth login races against cancellation; Esc cancels `/mcp reauth` + `/mcp add` flows.
2. Callback port: fail fast when busy, but preserve random-port fallback for fresh DCR flows.
3. Force login screen before consent on `/mcp reauth`; align prompt behavior with MCP SDK.
4. Preserve npx and non-npx cmd-shim direct launch; reuse gemini oauth helper.
