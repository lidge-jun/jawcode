## Why This Sub-Card

This slice covers the boundary between selector parsing, native match-fetch limits, post-fetch filtering
and ordering, and the read/search result window exposed to the model. OMP owns that seam in
`packages/coding-agent/src/tools/grep.ts` and `read.ts`; JWC has no `grep.ts` and instead owns content
search in `packages/coding-agent/src/tools/search.ts`, with native grep in `packages/natives/`, shared
scope resolution in `path-utils.ts`, and embedded read selectors in `read.ts`.

The naming difference is behavioral, not cosmetic: JWC search budgets matches globally, groups and caps
them per file, and emits a round-robin file window, while JWC read accepts a broader embedded selector
grammar. These anchors are therefore checks on budget/order/omission invariants at those JWC owners, not
a request to recreate OMP's grep API.

## Reference Decisions

| commit group | decision | rationale |
| --- | --- | --- |
| Fetch budget and ordering (`029720298`, `81a774983`) | **reference/compare** | Bounded native retrieval before JS filtering is a portable safety and correctness property. JWC already fetches with `INTERNAL_TOTAL_CAP`, then groups, per-file caps, paginates, and round-robin emits; equivalence should be judged against that search contract rather than OMP's ranged-grep algorithm. |
| Directory selectors (`f9b425f4b`) | **reference** | OMP proves that directory-scoped line selection can be coherent. JWC search currently accepts path arrays/globs/internal URLs, while directory line selectors live only on the read side and reject multi-range listings, so product grammar must be decided before any adaptation. |
| Empty selector fields (`2553495d0`) | **reference/adapt by invariant** | An omitted selector should not become an accidental zero/empty range. JWC's embedded read selectors and strict search schema do not share OMP's field shape; validate omission at each existing parser boundary without importing deprecated argument fields. |
