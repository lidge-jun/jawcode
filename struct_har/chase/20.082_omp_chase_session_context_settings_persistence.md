`447eb51f2` notes (wp18): JWC carried the vulnerable shape. Persistence is lazy (`_persist` waits for an
assistant message), so a post-`/new` breadcrumb points at a file that does not exist yet;
`readTerminalBreadcrumb` collapsed that to `null` and `continueRecent` fell back to `findMostRecentSession`
— the pre-`/new` transcript. Reproduced end-to-end before fixing. The reader now reports
`{ sessionFile, exists }` and only a genuinely absent breadcrumb triggers the fallback.

Test: `packages/coding-agent/test/session-continue-fresh-boundary.test.ts`, with controls for "target did
materialize" and "no breadcrumb at all" so the fix cannot pass by disabling `--continue`.

`4d685bf76` notes (wp17): not a port. Upstream's root cause — `abort()`'s finally draining while
disconnected — is already excluded in JWC, where `#resetInFlight` deliberately does not drain. The live door
was `#promptQueuedHiddenNextTurnMessages`, which had no disconnection guard, so a triggering hidden message
queued during `clearContext()` started a turn against the old context and landed its output in the fresh
session. Reproduced against a real `AgentSession` before fixing.

Test: `packages/coding-agent/test/agent-session-new-session-queued-steer.test.ts`, which pairs the
mid-transition assertion with a normal-operation control so the guard cannot pass by disabling the feature.
