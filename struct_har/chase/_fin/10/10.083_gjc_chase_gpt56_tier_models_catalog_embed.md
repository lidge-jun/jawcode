## Implementation Pressure

The static catalog, thinking policy, profile presets, selector state, and executor routing form one contract. Adding model IDs without matching context and effort metadata risks incorrect compaction thresholds; changing presets without catalog support risks failed activation or unintended fallback.

The catalog embed is a release boundary. Source-mode tests can pass while a compiled binary fails before command dispatch, so closure requires launching the actual compiled JWC artifact and resolving at least one bundled model.

## Risk Notes

Do not assume GPT-5.6 tier availability from an upstream catalog snapshot alone. Confirm current provider exposure before implementation, then pin tests to JWC's accepted model contract.

Do not conflate bundled `packages/ai/src/models.json` with the user-customized `.jwc/agent/models.json`. The file-type embed fixes the former; user registry loading remains a separate runtime path.

Persist effort only when valid for the resolved model/profile. Tests should cover batch selection, role badges, CLI/profile activation, restart, legacy aliases, and a model switch that cannot accept the stored level.

Any public examples, paths, package names, or release commands must use `jwc`, `.jwc`, and `@jawcode-dev`; upstream identifiers are evidence only.
