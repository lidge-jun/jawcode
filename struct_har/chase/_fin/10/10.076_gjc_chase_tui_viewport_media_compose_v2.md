## Why This Card Exists

GJC's v0.8→v0.9 TUI stream contains several independent slices that can improve JWC:
viewport repaint stability, kitty image idempotence, pasted/dragged image ingestion,
composer queue correctness, editor paste correctness, and a new regression-bisect tool.
This is not a single cherry-pick. JWC already has substantial TUI edits and local visual
constraints, so each slice needs an import/adapt/reject decision against owner files.

## WP7 Closure (2026-07-11)

**Verdict: ACCEPT.** The only confirmed transcript-corrupting defect in the owned surface was Kitty's non-idempotent `a=T` repaint. JWC now uploads each content-derived image id once with `a=t`, gives every `Image` instance a stable placement id, and replays only cursor-neutral `a=p` placements from the first reserved row. This prevents duplicate placements, sibling erasure, payload retransmission, and viewport-top cursor-up misplacement.

Markdown HTML comments are now hidden while surrounding text and non-comment HTML-like text remain visible. The macOS hardware-cursor path now re-anchors after synchronized render writes, preserving IME candidate placement. Existing JWC worktree changes already cover multiline insertion, filtered-empty-paste undo safety, bracketed-paste buffering, and viewport cursor preservation.

The remaining upstream slices are accepted without import: pasted file-path attachment is convenience polish because clipboard image attachment already works and failed-path fallback would require a new owner outside WP7; the bisect tool is a new destructive-adjacent feature, not an edit-safety correction; the broad runtime performance patch is optimization work with no reproduced crash or data-loss defect.
