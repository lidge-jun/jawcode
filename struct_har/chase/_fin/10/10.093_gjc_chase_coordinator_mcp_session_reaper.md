## Worktree Verification

JWC has `packages/coding-agent/src/coordinator-mcp/server.ts` with `jwc_coordinator_start_session`, prompt delivery, durable turn reads, session status/tail reads, a mutation gate, and `tmux has-session` liveness checks. `packages/coding-agent/src/session/session-storage.ts` also exposes `deleteSessionWithArtifacts()`.

The coordinator tool list and source sweep contain no `stop_session`, session-reaper module, or owner-proof idle cleanup path. The stdio runner awaits each request inside its input loop, so it has neither upstream's bounded concurrent pump nor its overload tests. The tmux probe is a direct `has-session` check and does not encode the upstream distinction between tmux 3.7 no-server diagnostics and transient spawn failure. ACP keeps an in-memory session map and artifact deletion exists elsewhere, but the upstream deletion wire/owner contract is not demonstrated on the JWC ACP surface.

## Decision Log

1. Adapted the upstream idle-reaper controller as a pure injectable module with clamped TTL/sweep intervals and non-overlapping sweeps.
2. Reaping requires all four predicates: coordinator-ephemeral, owner-proven, no active durable turn, and idle beyond the configured TTL.
3. Session records now carry the coordinator owner kind and namespace when created; records without that proof fail closed.
4. `jwc_coordinator_stop_session` requires the existing sessions mutation class plus per-call `allow_mutation: true`.
5. Direct tmux shutdown proves the recorded session name, pane id, and canonical pane cwd before `kill-session`, then confirms disappearance before deleting metadata.
6. Deterministic tmux no-server/missing-session output is distinguished from transient probe failure; transient failures retain metadata for retry.
7. The stdio pump caps active data handlers and queued requests, emits `server_busy` on overflow, and lets ping frames bypass saturated data slots.
8. Verification: 25 focused coordinator tests passed; targeted Biome passed. Package type checking reported no errors in the changed coordinator files and remained blocked only by pre-existing parallel-work errors in `packages/ai/src/providers/cursor.ts` and `file-lock-gc-toctou.test.ts`.
