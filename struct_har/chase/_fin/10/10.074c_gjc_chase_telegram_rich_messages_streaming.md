## WP6 Resolution — 2026-07-11

**ADAPT complete in JWC owners.** telegram-html provides escape-first Markdown rendering and balanced
4096-character splitting. turn-stream mirrors full finalized assistant turns by default, suppresses
dot-only output, and emits throttled live previews only when JWC_NOTIFICATIONS_STREAM=1. Live and final
frames share a stable messageRef. telegram-turn-delivery serializes sends, edits the live message in
place, and sends final overflow chunks in order. The loopback server owns the sink; AgentSession adds only
the notification event hook.

Rich command parsing is available through config and bot-aware parsers. A second durable daemon preference
was intentionally not added: safe rich HTML is global for active delivery and settings remain the single
configuration authority. Runtime proof covered hostile-tag escaping, three balanced chunks for 9,000
characters, live send followed by final edit, and matching refs. The notification suite passed 239 tests.

## Scope

Import rich Telegram rendering, the durable `/rich` toggle, live turn streaming with in-place Telegram edits, full finalized turn delivery, dot-only completion suppression, and flat fallback nudge copy. This is an adaptation slice because JWC uses `threaded-surface.ts`, lifecycle modules, and Telegram media/render owners rather than GJC's `threaded-render.ts` and `telegram-daemon.ts` layout.
