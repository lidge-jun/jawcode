## Chase Scope

This card treats model routing as one stateful contract. Canonical variants, provider availability, credentials, fallback rotation, retry delay, subagent resume, and cache economics all influence which concrete model may run next. A refresh or retry must not silently replace a session-sticky model, revive an exhausted fallback entry, reject a keyless provider, or return before terminal retry state has settled.

JWC already has a canonical model registry and resolver, session-aware credential lookup, keyless-provider handling, retry lifecycle events, and subagent auth-fallback tests. The upstream implementation also introduces dedicated fallback transport, fallback-chain controller, cache-economics, and adversarial-routing owners that do not exist at the same JWC paths. The chase must compare behavior and ownership together rather than importing those modules mechanically.
