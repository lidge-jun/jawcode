## Implementation Evidence

- `5003246` — strict UTF-16 decoder in `crates/pi-natives/src/linediff.rs` (rejects unpaired surrogates with `InvalidArg` instead of substituting `U+FFFD`); static ESM loader in `packages/coding-agent/src/edit/diff.ts` replacing a `createRequire` that could never resolve; `crates/pi-ast/src/tags.rs` `tags_query` made `const fn` to unblock a pre-existing `check:rs` clippy failure.

### The finding that mattered most

`edit/diff.ts` resolved the addon with `createRequire`, but `@jawcode-dev/natives` declares an **`import`-only** `exports` condition. The require therefore always threw `MODULE_NOT_FOUND`, was swallowed as "native unavailable", and **every diff in JWC silently ran the pure-JS path the native port exists to replace.** Every other native consumer in the tree uses a static ESM import; `edit/diff.ts` was the lone outlier.

Measured after the repair, on the pathological case the code comment describes:

| workload | jsdiff | native | speedup |
|---|---|---|---|
| 556 KB, sparse changes | 5 ms | 2 ms | 2.1× |
| 224 KB, heavy divergence | 17,848 ms | 1,168 ms | **15.3×** |

Ordering was forced: reviving the loader alone would have newly exposed the `U+FFFD` corruption to users, so the decoder had to land in the same commit.

### Open decision for the user

Ill-formed model tool input is written to disk as `EF BF BD` **before** the diff is generated, so a diff that "preserves" a lone surrogate would show something other than what was persisted. The correct contract — reject ill-formed edit input before writing, or diff the re-read file — changes tool behavior and is the user's call. This cycle only makes the two diff engines agree.
