## Chase Scope

This card tracks the full persistent-limit state flow: parse provider errors, preserve the strongest classifier, mark a credential unavailable, rank or rotate accounts, reconcile reported usage to the request identity, reset the selected account, invalidate stale usage caches, and accept login-sourced broker snapshots.

The distinction is operationally important. A quota or spend limit must not be retried like a transient 429, while content filtering must not accidentally become a credential-rotation signal. JWC already has central rate-limit parsing, credential ranking, usage providers, broker snapshots, and invalidation hooks, but several OMP-specific owners are absent. The card therefore prioritizes classifier and identity tests before code transfer.

- [ ] Add/confirm fixtures for Anthropic spend limits, OpenRouter daily limits, generic quota exhaustion, and content filters.
- [ ] Prove classifier composition cannot downgrade an existing persistent usage-limit result.
- [ ] Prove the same credential identity flows through usage attribution, ranking, rotation, reset, and broker snapshots.
- [ ] Verify cache invalidation updates the in-memory broker view before callers continue.
- [ ] Keep all current `packages/ai` worktree changes intact while comparing behavior.
