The work is infrastructure rather than a user feature, but failures here can publish an incomplete package set or make release gates non-deterministic.

JWC already owns affected-path and release-publish scripts plus the canonical release workflow. Adoption must preserve JWC's OIDC-first release contract, current package inventory, and repository context. Upstream workflow YAML is evidence, not a file-for-file import target.
