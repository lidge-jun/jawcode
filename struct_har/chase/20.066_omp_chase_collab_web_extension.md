## Chase Scope

This cluster joins two related boundaries. The collab transcript must preserve message Markdown, in-flight tool arguments, and one visible row per tool call. The extension/RPC side must preserve the same ordering while loading compiled modules, rewriting failed tool results, queueing user messages, and closing stdin-backed transports safely.

JWC has no `packages/collab-web`, so the transcript commits are reference contracts for any bridge, export, or transcript UI rather than direct ports. JWC does have extension wrappers, steer/follow-up queues, RPC mode, and ACP adapters. Those owners should be compared behavior-first, with special attention to tool-use/tool-result adjacency and teardown after EOF.

- [ ] Keep collab transcript changes reference-only unless JWC adds an equivalent web transcript owner.
- [ ] Verify thrown tool failures still pass through extension `tool_result` rewriting.
- [ ] Verify sequential queue, steer, and follow-up ordering across TUI, RPC, and ACP entry points.
- [ ] Verify malformed RPC frames remain observable and EOF fails host tools closed.
- [ ] Verify ACP and RPC teardown await durable cleanup without hanging stdin dialogs.
