## Implementation Pressure

Vanish evidence is a reliability and forensic-debugging gap. Without persisted raw evidence, a session can disappear after prompt acceptance and leave only derived or missing state, making recovery and blame assignment hard.

Postmortem recoverability is a lifecycle gap. A postmortem handler should preserve enough state for follow-up sessions while still restoring the terminal and flushing session manager state.

Install atomicity is a user-data safety gap. Failed upgrades should never delete or corrupt an existing working `jwc` binary.

CI affected-test splitting is a throughput gap, not a runtime correctness gap. Treat it as separate from session recovery unless a promotion bundle explicitly includes CI hardening.

## Risk Notes

Do not copy upstream `scripts/gjc-session/*` paths verbatim into JWC-facing docs or code. Public names must be `jwc` and `.jwc`.

Do not alter `packages/tui/src/tui.ts` or curated TUI scroll behavior while handling the tmux replay storm unless the implementation is explicitly scoped to the known scroll contract.

Any session-state format change may need migration or tolerant readers. Prefer additive fields and tests around missing/undefined records.

Install-script changes must preserve current JWC package naming, binary name, and release URL contract.

CI sharding changes should be proven against JWC's actual test runner and scripts, not upstream assumptions.
