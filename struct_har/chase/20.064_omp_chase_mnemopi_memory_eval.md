# 20.064 — omp chase: mnemopi memory and isolated eval runtimes

> MOC: [20_omp_chase_MOC](./20_omp_chase_MOC.md) · G2 · ⬜ · P3 — protect durable memory while keeping eval cwd, IPC, timeout, and URI resolution isolated.
> Reviewed source: OMP `7aa1d581c..b0d04e517` (`origin/main`, v16.4.2→v17.0.1) vs JWC worktree.

## Chase Scope

This card joins two isolation problems without assuming one implementation owner. OMP's mnemopi changes protect durable working memory during trim, make candidate selection transactional, cascade linked artifacts deliberately, and recover embedding-runtime loading on Windows. Its eval changes separate terminal and eval lifecycles, preserve per-cell cwd, propagate IPC clone failures, retain fallback execution, and pass URI selectors structurally to host resolution.

JWC has no `packages/mnemopi/`. Its memory product supports `off`, `local`, and `hindsight` backends through `jwc-runtime/memory-runtime.ts`, while `memory://` routing enforces root containment. The eval architecture is also different: JWC uses a Bun worker with an inline fallback, not OMP's lazy process-entry and agent-bridge layout. Memory and eval therefore require separate implementation units even though the upstream cluster records both as isolated runtimes.

All 32 D14 commits are retained. Autolearn and compaction follow-ups remain cross-card evidence and must not silently expand an eval fix.
